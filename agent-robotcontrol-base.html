Robot Control Base

The robot arm that will let the Live Control Plane agent act in the physical world — waving, pointing, and reacting on stream. Planned as a standalone Python repo in the LeRobot ecosystem.

status: in design — not built yet Python · LeRobot Tool-contract implementation

Status

in design — goals and contract defined, no code yet

This page describes a plan, not a finished project. The livestream side (Live Control Plane) exists and already calls tools through a fixed interface; this repo will be the execution end that makes those calls move a real arm. Everything below is the design for that.

Goals

Physical presence on stream

Give the livestream agent a body: a small robot arm on the desk that can wave, point, pick up light props, and react visibly when the audience swaps its persona.

Implement the Tool contract

Each whitelisted tool in the control plane — with zod-schema arguments, a ToolContext carrying an AbortSignal for barge-in, and a typed ToolResult ok/error — gets a real hardware implementation here.

LeRobot-native

Build on the LeRobot ecosystem for robot interfaces, calibration, and (later) learned policies, instead of a one-off driver stack.

Safe by default

Serial execution, joint-limit enforcement, and honoring AbortSignal mid-motion so a barge-in from the stream stops the arm cleanly.

The Contract It Implements

The interface is owned by the control plane; this repo never changes it, only satisfies it.

Why a Separate Repo

  • Different iteration speeds: hardware bring-up, calibration, and driver work churn constantly; the stream logic shouldn't have to.
  • Different stacks: the control plane is TypeScript; the robotics ecosystem that matters here (LeRobot) is Python.
  • A real boundary: the Tool contract is the only coupling. Each side can be developed, tested, and replaced independently — the control plane already runs against a mocked execution end.

Plan

  • Step 1 — mock-faithful server: a Python service exposing the Tool contract, initially driving a simulated arm so the control plane can integrate against it end-to-end.
  • Step 2 — hardware bring-up: pick an arm supported in the LeRobot ecosystem, wire up calibration and basic motion primitives.
  • Step 3 — stream-ready motions: a small library of expressive, interruptible motions mapped to the whitelisted tools.
