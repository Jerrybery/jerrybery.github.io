Live Control Plane

An AI co-host for Bilibili livestreams whose personality the audience can vote to swap in real time. Chat messages become votes, votes hot-swap the agent's persona, and a dual-layer agent answers fast first and thinks second — with its name rendered on the OBS overlay.

TypeScript · pnpm mock-first MVP vitest

Overview

A Bilibili live room is a chaotic environment: hundreds of danmaku messages per minute, no turn-taking, and an audience that expects instant reactions. This project is the control plane for an agent that can survive that — it ingests the chat, lets the audience steer who the agent is, and keeps every action behind a whitelisted, validated tool boundary.

The MVP is deliberately pure software with mocked edges: a scripted danmaku replay stands in for the Bilibili open-platform WebSocket, and an offline mock LLM stands in for the model when no API key is configured — so the whole pipeline runs and is tested (vitest) without network, credentials, or hardware.

Pipeline Stages

DanmakuSource

Bilibili live-chat (danmaku) ingestion in the open-platform WebSocket style. The MVP replays a scripted message log so demos and tests are deterministic.

VoteAggregator

Time-windowed majority vote over chat messages, deduplicated per user id — one viewer, one vote per window, no ballot stuffing.

PersonaManager

Persona cards bundle a system prompt, a tool whitelist, and a reflex style. A winning vote hot-swaps the active persona and broadcasts PersonaSwitched to the rest of the system.

Agent — dual-layer

A synchronous rule-based reflex layer replies instantly; a streaming LLM reasoning layer fills in the substance behind it. The LLM client talks to any OpenAI-compatible endpoint over native fetch SSE, and degrades to a mock LLM when unconfigured.

ToolRegistry

Every tool declares zod-validated arguments and runs through a serial execution queue. The active persona's whitelist decides which tools exist for the agent at all.

OutputSink + OBSController

Agent output is pushed to the stream overlay via obs-websocket — the current persona's name is rendered on screen so the audience always knows who they're talking to.

Implementation Highlights

  • Barge-in: a higher-priority message cancels the in-flight LLM stream via AbortController — the reflex layer has already answered, so interrupting the reasoning layer never leaves the stream silent.
  • Reflex-first latency story: rule-based replies go out synchronously, so perceived response time doesn't depend on model latency.
  • Streaming over native fetch: SSE parsing on top of the Fetch API, no SDK dependency — the client works against any OpenAI-compatible server.
  • Safety by construction: zod-validated args, a per-persona tool whitelist, and a serial execution queue mean the agent can only ever do a small set of well-formed things, one at a time.
  • Mock-first MVP: scripted danmaku replay plus a mock LLM make the entire loop reproducible in CI with vitest.

The Tool Contract

The Tool interface is the cross-repo contract: the control plane owns the interface, and the planned Robot Control Base repo will implement the execution end so whitelisted tool calls physically drive a robot arm on stream. 

interface Tool {
  name: string
  args: z.ZodSchema            // args validated before execution
  call(args, ctx: ToolContext): Promise<ToolResult>
}

interface ToolContext {
  signal: AbortSignal          // barge-in propagates into tools
}

type ToolResult = { ok: true, data: ... } | { ok: false, error: ... }

Because the contract carries an AbortSignal and a typed ok/error result, the execution side can be swapped — mocked today, a real arm tomorrow — without the agent, persona, or vote logic changing at all.
