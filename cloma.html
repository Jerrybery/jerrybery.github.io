Memory benchmark · failure attribution

CLOMA

Closed-Loop Memory Assessment — a diagnostic benchmark for long-term memory systems. Not a leaderboard: CLOMA runs a memory system through scripted scenario chains and attributes every failure to a specific layer, so you see where your system breaks, not just that it breaks.

Python · CLI Plugin adaptor interface LLM judge + human calibration

Overview

Most memory benchmarks tell you a score. CLOMA tells you a layer. A chain plays a persona through a multi-scene story that writes, updates, contradicts, and queries memories; probes then check what the system actually stored, found, and concluded — and the attribution engine classifies every failure into one of six layers along the path from write-time storage through retrieval to read-time reasoning.

Chains exercise memory under three dynamic source dimensions: a user-feedback closed loop, external (exogenous) state changes, and asynchronous background processing — the conditions under which real agents actually drift.

Core Concepts

Scene chains

YAML-defined sequences of memory-atom injections. Each chain plays a persona through a multi-scene story; chains are sized Tier 1–3 by atom count, scene count, and noise volume.

Six-layer attribution

Every probe outcome is classified into L1a, L1b, L2, L3, L4a, or L4b — storage, drift, update, retrieval, reasoning, and noise rejection. An L4b score of None vs 0.0 distinguishes "no noise to reject" from "all noise rejection failed".

Plug-in adaptors

Systems under test implement the BaselineAdaptor interface and are discovered via the cloma.adaptors entry-point group. Built-ins: dummy, naive_vector_db, claude_code, openclaw, zep_graphiti, hindsight, mem0.

LLM Judge & Human Calibration

During attribution, an LLM judge scores probe answers — most notably the semantic noise-rejection judgment behind L4b: mentioning noise only to dismiss it is acceptable; leaking it as fact is not.

Because judge reliability bounds metric trustworthiness, CLOMA ships a human-calibration panel: it extracts a stratified sample of judged probes, lets a human verifier agree/disagree in the browser, and reports human-vs-judge agreement with Cohen's kappa and per-layer confusion.

Evaluation Chains

  • 10 formal chains: T1×3 / T2×4 / T3×3 across the software, healthcare, and enterprise domains.
  • Review before run: cloma review statically checks a chain config, with optional LLM-based D-level validation.
  • Repeatable runs: cloma run supports N repetitions per chain/adaptor; artifacts (per-run reports, D-level results, aggregate summary) are organized by date, chain, and adaptor.
