Multi-user household agent · memory system

Cyborg

An agent built for the multi-user household: every family member gets an independent identity and memory, daily conversation accumulates each person's preferences and habits, and offline consolidation catches cross-member contradictions — dad says Saturday, mom booked Sunday.

Python · FastAPI-style web + SSE Docker / docker-compose MIT

Overview

Most agents are single-user by assumption. Cyborg starts from the opposite premise: it lives in a household. Each family member talks to it through their own session, and the agent keeps per-user identity and memory strictly separate — preferences, habits, and history accumulate per person over daily conversation.

The interesting problems only appear between users: one person's "we leave Saturday" is another's "hotel booked for Sunday". A single offline pass with access to everyone's memory — the Dream engine — is where those contradictions surface.

Memory Hierarchy

Memory is organized as six layers, L1–L6, from prompt-level instructions up to offline consolidation. The lower layers stay close to the live context; the three engines below do the long-term work.

L4 — daily diary (DistillEngine)

Each day's session is distilled into a diary entry per user. L4 is per-user isolated — no cross-user visibility at this layer.

L5 — long-term memory

Durable facts organized as USER / FAMILY / RECENT. Writes go through an auth-gated layer (distill_tools), so long-term memory is never modified without an explicit, checked write path. Also per-user isolated.

L6 — Dream engine

The only layer that does cross-user analysis. Running offline over L4/L5, it consolidates and catches contradictions between members — the Saturday-vs-Sunday class of conflicts.

Temperature-Driven Consolidation

Dream runs are not on a fixed schedule. A temperature model tracks the information backlog — information drift plus scene changes — and triggers the Dream engine only when the backlog is hot enough. Consolidation cost scales with actual change, not wall-clock time, which cuts token spend on quiet days.

Tagged memory files let Dreaming trace hierarchical relationships between memories, so a consolidation pass can find and update exactly the affected files instead of rewriting wholesale.

Multi-User by Design

Per-user session

One session per user per day. WeChat (ClawBot) and the web SSE channel feed into the same context, so a conversation started on one channel continues seamlessly on the other.

CompactEngine

Zero-latency context reorganization: the context window is managed against a limit of 0.83 of the model's context, with a configurable compression threshold.

MCP tool architecture

Built-in tools plus extension over the MCP protocol, backed by a multi-provider LLM client (Anthropic / OpenAI / DeepSeek).
